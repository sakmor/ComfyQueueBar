# 動画の進捗監視をアプリに任せる：エージェントのトークン節約ガイド

[English](../AGENT_TOKEN_GUIDE.md) · [简体中文](AGENT_TOKEN_GUIDE.zh-CN.md) · [繁體中文](AGENT_TOKEN_GUIDE.zh-TW.md) · [日本語](AGENT_TOKEN_GUIDE.ja.md)

動画生成には数分以上かかることがあります。エージェントが数秒ごとに新しいモデルのターンを開始して進捗を照会・解釈すると、待機中もトークンを消費します。ComfyQueueBar は指定ジョブをアプリで監視し、エージェントは購読の設定、イベント受信、チャット再開時の結果処理を担当します。

**既存の ComfyUI 動画ジョブの完了を確認したいとき、エージェントによる繰り返しの進捗確認を減らせます。** 画像ジョブにも使えます。

## 1. アプリ、MCP、skill を設定する

1. [GitHub Releases](https://github.com/sakmor/ComfyQueueBar/releases/latest) から最新の Apple Silicon アプリをダウンロードします。macOS 13 以降が必要です。Intel Mac は [ソースからビルド](../../README.md#build-from-source)してください。
2. アプリの歯車設定で ComfyUI のアドレスを入力し、接続します。リモート接続には [SSH 転送](../REMOTE_SETUP.md)も使えます。
3. **AI エージェント連携**を有効にして、**Claude／Codex を設定**を押します。MCP adapter は Python 3.9 以降、Codex の自動登録は利用可能な Codex CLI が必要です。
4. 設定結果を確認します。MCP 登録と skill インストールは別々に報告されます。skill のインストール成功だけでは MCP 接続を確認できません。
5. エージェントのセッションを開き直します。ツールが表示されない場合はデスクトップアプリも再起動してください。

設定は adapter と共通 skill をインストールし、置き換える設定・skill をバックアップします。ComfyQueueBar の更新後は設定を再実行し、セッションを開き直してください。

アプリを起動したままにし、Mac をスリープさせないでください。スリープ、アプリ終了、連携無効の間は監視が停止します。

## 2. 接続を確認する

Codex に貼り付けます。

```text
$comfyqueuebar 接続を確認し、アプリ、ComfyUI、履歴が利用可能か教えてください。
```

Claude Code では次を使います。

```text
/comfyqueuebar 接続を確認し、アプリ、ComfyUI、履歴が利用可能か教えてください。
```

アプリの利用可否、ComfyUI の接続・履歴の状態、実行中・待機中の件数を確認できます。0 件は空のキューの場合もあるため、接続状態で判断してください。

この操作は状態を一度読み取るだけで、ジョブ送信や購読作成は行いません。

## 3. 正しい prompt ID を取得する

`prompt_id` は ComfyUI が個々の送信に割り当てる完全な識別子です。ワークフロー名、ファイル名、ノード ID、生成用のプロンプト文とは異なります。

- **エージェントやプログラムから送信した場合：** `/prompt` の応答にある完全な `prompt_id` を使います。同じ会話にその送信 ID がある場合は、エージェントにそれを使うよう依頼できます。
- **ComfyUI の画面から送信した場合：** ブラウザーの開発者ツールの Network パネルで該当する `/prompt` リクエストを探し、JSON 応答の `prompt_id` を確認します。送信時刻が対象ジョブと一致することを確認してください。
- **実行中・待機中の場合：** `/queue` の `queue_running` と `queue_pending` にある各ジョブ配列の2番目の項目が完全な ID です。対象を特定し、先頭のジョブが自分のものだと決めつけないでください。

アプリでは短縮 ID が表示されることがあります。購読には完全な ID が必要です。以下の `YOUR_PROMPT_ID` を実際の ID に置き換えてください。

## 4. 一度購読してアプリに任せる

Codex に貼り付けます。

```text
$comfyqueuebar 送信済みの ComfyUI 動画ジョブを確認してください。prompt ID は YOUR_PROMPT_ID です。
このジョブだけを購読し、一度だけ待機してください。進捗を繰り返し照会しないでください。
実際の状態と、後から確認を再開するための subscription_id を報告してください。
```

Claude Code では先頭の `$comfyqueuebar` を `/comfyqueuebar` に置き換えます。

エージェントは接続を確認し、アプリが返したサーバーアドレスで購読を作成して `subscription_id` を保存します。終了状態の結果があれば直接処理し、それ以外は通常一度だけ最大45秒待機します。ホストの制限により短くなる場合があります。

待機中は通常のプログラムがイベントを確認し、毎秒モデルを呼び出すことはありません。ツールの結果を解釈するときは、エージェントの推論を使用します。

| 状態 | 意味 | 次の操作 |
| --- | --- | --- |
| queued | キューで待機中 | 購読 ID を保存し、後で確認 |
| running | 実行中 | アプリに監視を任せ、後で確認 |
| completed | 明示的に完了 | 出力参照を依頼、または動画を確認 |
| failed / interrupted | 明示的な失敗・中断 | エラーを読み、対応を決める |
| unknown | まだ確認できない | ID、履歴、サーバーを確認し、成功と判断しない |

タイムアウト、切断、履歴の利用不可は待機・監視の状態であり、ジョブの成功や失敗を示すものではありません。購読 ID は保存された監視記録、prompt ID は ComfyUI ジョブを識別します。

## 5. アプリの通知後に確認を再開する

設定で必要な完了・失敗通知を有効にし、macOS の通知を許可します。チャットに戻る目安として使ってください。アプリの通知はキューと通知設定に従うため、指定ジョブの確認には購読結果を読み取ります。

**標準 MCP は動画完了時に待機中の Codex や Claude のチャットを自動的に起動しません。** アプリが結果を保存し、後から読み取れます。45秒ごとの待機の繰り返しや、毎分モデルを起動する自動化は避けてください。

後で Codex に貼り付けます。

```text
$comfyqueuebar 購読 YOUR_SUBSCRIPTION_ID の確認を再開してください。
保存済みの結果を読み、未完了なら一度だけ待機してください。照会をループしないでください。
```

セッションを開き直した後も保存した ID を使えます。Skill は `resume_subscription` で元の購読を接続し直し、同じ確認のために新たな購読を作りません。

待機せず現在の記録だけ読む場合：

```text
$comfyqueuebar 購読 YOUR_SUBSCRIPTION_ID の保存済み結果を読んでください。今回は待機しないでください。
```

## 6. 出力を取得し、次の作業を指示する

Skill は通常、簡潔な状態を返します。動画の出力情報は明示的に依頼してください。

```text
$comfyqueuebar 購読 YOUR_SUBSCRIPTION_ID を確認し、完了していれば動画の出力参照を一覧にしてください。
```

参照には ComfyUI のファイル名、サブフォルダー、`/view` URL が含まれます。エージェントのローカル環境にダウンロード済みとは限りません。アプリの完了履歴の **Preview & download…** からもプレビュー・ダウンロードできます。

追加処理には「完了を確認したら、このフォルダーに動画をダウンロードし、長さを確認して」のような具体的な指示を出してください。ダウンロード、編集、再送信には対応するツールと作業指示が必要です。この skill は既存ジョブの確認を担当します。

完了・失敗・中断後、この手順で作った確認用購読は監視を終了し、記録は残ります。別の作業から再開した購読は勝手に解除しません。購読を解除しても ComfyUI ジョブは停止しません。

## どこでトークンを節約するのか

| 段階 | エージェントによる繰り返し確認 | ComfyQueueBar |
| --- | --- | --- |
| 設定 | エージェントが確認方法を決める | 接続確認と一度の購読 |
| 生成待ち | モデルのターンで照会・解釈し、再確認を判断 | アプリのタイマーと MCP のプログラム待機。言語モデルを呼び出さない |
| 結果処理 | 完了やエラーを解釈 | イベント受信時やチャット再開時に解釈 |

例えば10分の生成中、10秒ごとに新しいモデルのターンで確認すると約60回の確認になります。一度の購読、一度の時間制限付き待機、完了後の確認に変えることで、繰り返しの進捗確認ターンを避けられます。これは手順の例で、**トークンのベンチマークや固定の削減率ではありません**。イベントで待機が早く終了する場合もあります。

削減するのは待機中の繰り返しのモデル処理です。購読設定、ツール結果、エラー対応、後続の動画処理にはトークンを使用します。既に通常のプログラムだけで監視している場合、追加の削減は小さい可能性があります。

## トラブルシューティング

| 問題 | 対応 |
| --- | --- |
| Skill が見つからない | 設定を再実行し、インストール成功を確認してセッションを再開 |
| Skill はあるが MCP ツールがない | 登録結果と MCP 一覧を確認。Claude Code は `/mcp` を使用可能 |
| アプリが利用不可 | 起動、連携有効、Mac の覚醒を確認。ハートビート期限切れでも利用不可になる |
| unknown が続く | 完全な ID、サーバー、履歴を確認。削除された履歴は完了の証拠にならない |
| サーバー切り替え後に更新されない | 元に戻す。旧購読は一時停止し、別サーバーには移行しない |
| 優先実行後に元のジョブが消えた | Prioritize は再送信して prompt ID を変更する。新しい ID を確認して購読 |
| 待機がタイムアウトした | 購読 ID を保存し、通知後か後ほど再開。モデルの照会ループを作らない |
| 自動で次の作業を開始したい | 標準 MCP は待機中チャットを起動しない。実験的な Claude Channels は入信の検証が必要で、登録成功だけでは保証できない |

手動設定、配信モード、データ保存については [連携ガイド（英語）](../AGENT_INTEGRATION.md)、skill の内容は [SKILL.md](../../.agents/skills/comfyqueuebar/SKILL.md)を参照してください。
