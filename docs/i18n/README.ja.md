# ComfyQueueBar

**macOS のメニューバーから、ワンクリックで ComfyUI のキューを確認。** 実行中のジョブや現在のノードの進捗を確認し、次に実行するジョブを選べます。

**エージェントのトークンを動画制作に。進捗監視は ComfyQueueBar に任せましょう。**

長い動画生成中にエージェントが繰り返し進捗を確認すると、モデルの応答やツール結果の処理でトークンを消費する場合があります。ComfyQueueBar では対象ジョブを一度購読し、アプリとプログラムによる待機が監視を担当します。イベント受信時やチャット再開時に結果を確認することで、進捗確認のためのモデル呼び出しを減らせます。

[詳しいトークン節約ガイド](AGENT_TOKEN_GUIDE.ja.md)

アプリの監視自体は言語モデルを呼び出しません。エージェントによる結果の処理にはトークンを使います。削減量は確認頻度、モデル、生成時間によって異なり、固定の削減率は測定していません。標準 MCP は待機中のチャットを自動的に起動しません。

## 完了履歴と新機能

- **Macを起こす**：保存済みアドレスに対象インターフェイスの MAC、ブロードキャスト IPv4、UDP ポートを設定し、手動で起動パケットを送信できます。選択中のサーバーに限り、オフライン時の自動送信も可能です。[設定手順と制限](REMOTE_SETUP.ja.md)を参照してください。

**15 秒**ごとに最新 **200 件**のサーバー履歴を読み込みます。過去 1 時間、24 時間、今日、読み込み済み履歴で絞り込み、ジョブ名や出力ファイル名を検索できます。時刻のない項目は読み込み済み履歴にのみ表示されます。「失敗と中断」を開くとサーバーのエラー詳細を確認できます。ComfyUI の履歴を消去すると項目も消えます。

- **プレビューとダウンロード**：サムネイルまたは Preview & download… をクリックし、出力を選択して画像／動画を表示します。Download… で保存先を選べます。MP4、MOV、M4V は macOS 対応コーデックが必要です。他の形式もダウンロードできます。
- **通知**：歯車でオフ、ジョブごと、キュー完了時を選択し、失敗／切断通知を個別に有効化できます。初期設定はオフで、macOS の許可が必要です。初回接続では過去の履歴を通知しません。
- **複数サーバー**：アドレスと名前を入力して Save address を押します。パネル上部のサーバー名から切り替えられます。監視は一度に 1 台です。
- **時間予測**：アプリが最初に観測した時点からの経過時間を表示します。同じ設定の成功履歴が 3 件以上あり、開始／終了時刻がある場合に残り時間を推定します。負荷やキャッシュで精度は変わります。

GPUtw の非公開・パスワード保護インスタンスは「設定 → GPUtw にログイン…」から利用できます。正しいサービスを開き、「この ComfyUI を確認」でポートと最近のジョブを確認してから「このサーバーを監視」を押します。期限切れの場合は再ログインしてください。Cookie はアプリの WebKit で管理し、保護された出力にも同じログイン状態を使います。詳しくは [GPUtw とリモート設定ガイド](REMOTE_SETUP.ja.md)を参照してください。

## 機能と動作要件

- SwiftUI 製のネイティブアプリ。Dock にウィンドウを表示せず、Electron は使用しません。自動更新にはオープンソースの Sparkle を使用します。
- 実行中と待機中のジョブの合計数をメニューバーに表示。各リストは **4 秒ごと**に更新します。
- ワークフロー名、短縮した prompt ID、ノード数、待機順を表示します。
- **Prioritize（優先実行）**：確認後、待機中のジョブをキューの先頭に移します。
- **Stop（停止）**：確認後、実行中のジョブの中断を要求し、待機キューは保持します。
- 任意のサーバー拡張機能を導入すると、現在のノード名と進捗率を **1 秒ごと**に更新します。
- サーバーアドレスの保存、手動更新、ローカル接続、SSH ポート転送に対応します。

| 項目 | 要件 |
| --- | --- |
| Mac | macOS 13 Ventura 以降 |
| ビルド | Swift 5.9 以降を含む適切な Xcode／Command Line Tools |
| ComfyUI | `/queue` と `/prompt` にアクセス可能であること。特定ジョブの停止には `/interrupt` が `prompt_id` に対応している必要があります |
| ノードの進捗 | `comfy_execution.progress.ProgressHandler`、`add_progress_handler`、`execution.reset_progress_state` を提供する ComfyUI |
| 拡張機能の環境 | ComfyUI 自身の Python 環境と既存の `aiohttp` を使用 |

アプリは macOS 専用です。リモートの ComfyUI は macOS、Linux、Windows で実行できます。ビルドで生成されるバイナリはビルドした Mac のアーキテクチャ用で、ユニバーサルバイナリではありません。古い ComfyUI や派生版では互換性が異なる場合があります。

## Skill で AI にジョブを確認させる

[詳しいガイド](AGENT_TOKEN_GUIDE.ja.md)では、そのまま貼り付けられる指示、完全な prompt ID の取得、結果の確認、トラブルシューティングを説明しています。

1. 最新版のアプリをインストールし、ComfyUI に接続します。
2. **設定 → AI エージェント連携 → Claude／Codex を設定**を実行し、エージェントのセッションを開き直します。アプリ更新後も再実行して skill と MCP adapter を更新してください。置き換えられる skill はバックアップされます。
3. Codex では `$comfyqueuebar 接続を確認して`、Claude Code では `/comfyqueuebar 接続を確認して` と入力します。
4. 既存ジョブは `$comfyqueuebar prompt ID <prompt_id> の結果を確認して` で確認できます。返された購読 ID を保存し、後で `$comfyqueuebar 購読 <subscription_id> の確認を続けて` と入力します。Claude Code では `/comfyqueuebar` を使います。

プレースホルダーを実際の ID に置き換えてください。Skill はジョブの送信やキューの変更を行わず、通常は一度だけ最大 45 秒待機します。タイムアウトは失敗や完了を意味しません。購読 ID で後から確認できます。標準 MCP は待機中のチャットを自動的に起動しません。アプリの完了・失敗通知後にチャットを再開してください。[詳しい手順とトラブルシューティング（英語）](../AGENT_INTEGRATION.md#use-the-comfyqueuebar-skill)も参照してください。

## クイックスタート

### 1. ビルドツールを準備する

```sh
xcode-select --install
swift --version
```

インストール済みの場合はインストールを省略できます。Swift が 5.9 以降であることを確認してください。古い場合は Command Line Tools を更新するか、適切な Xcode を選択します。

### 2. ダウンロードしてビルドする

```sh
git clone https://github.com/sakmor/ComfyQueueBar.git
cd ComfyQueueBar
bash build-app.sh
open build/ComfyQueueBar.app
```

スクリプトはリリース用バイナリとアプリバンドルを作成し、ローカルの ad-hoc 署名を付けます。このリポジトリの `build/ComfyQueueBar.app` のみを再作成します。ComfyUI のインストールや起動は行いません。

### 3. ComfyUI に接続する

1. 既存の ComfyUI を起動します。
2. macOS メニューバーの ComfyQueueBar アイコンをクリックします。
3. **ComfyUI アドレス** にアドレスを入力します。通常は `http://127.0.0.1:8188` です。
4. **接続**を押し、ポートと最近のジョブを確認してから **このサーバーを監視** を押します。
5. ComfyUI でジョブをキューに追加すると、次の更新時にパネルへ表示されます。

新しい有効な応答で空のキューを確認した場合は `0`、切断または情報が古い場合は `—`、ログインが必要な場合は `!`、初回確認中は `…` を表示します。数値は選択したポートの ComfyUI ジョブ数です。次のコマンドでも確認できます。

```sh
curl --fail http://127.0.0.1:8188/queue
```

### 4. ノードの進捗を有効にする（任意）

キューの監視だけなら拡張機能は不要です。ノードの進捗を表示するには、**接続先のサーバーを実際に動かしている ComfyUI** に拡張機能をインストールします。

```sh
bash install-comfyui-extension.sh /path/to/ComfyUI
# 空白を含むパスは引用符で囲みます
bash install-comfyui-extension.sh "$HOME/AI Tools/ComfyUI"
```

生成が終わるのを待ってから ComfyUI を再起動し、次のコマンドで確認します。

```sh
curl --fail http://127.0.0.1:8188/comfyqueuebar/queue-progress
```

進捗がまだ報告されていない場合、レスポンスの null 値は正常です。アプリは prompt ID が実行中のジョブと一致する進捗だけを表示します。**パーセント表示は現在のノードの進捗で、ワークフロー全体の進捗ではありません。** ノードが変わると最初からになる場合があり、進捗率を報告しないノードもあります。リモート接続では拡張機能をサーバー側にインストールしてください。

## 通常のアプリとしてインストールする

```sh
mkdir -p "$HOME/Applications"
cp -R build/ComfyQueueBar.app "$HOME/Applications/"
open "$HOME/Applications/ComfyQueueBar.app"
```

置き換える前に既存のアプリを終了してください。ログイン時に起動するには、macOS の「システム設定 → 一般 → ログイン項目」でアプリを追加します。名称は macOS のバージョンによって異なる場合があります。アプリによる自動登録は行いません。

## キュー操作の仕組み

**Prioritize** は選択したワークフローを `front: true` で再送信してから元の待機項目を削除します。prompt ID は変わりますが、現在実行中のジョブは中断しません。複数のリクエストを使うため、途中で接続が切れたり元のジョブが実行を開始したりすると、競合や重複が起こる可能性があります。アプリは復旧を試み、結果を確認できない場合は ID を報告します。再試行する前にキューを確認してください。

**Stop** はキューを再確認してから、選択した実行中ジョブの prompt ID を `/interrupt` に送信します。待機ジョブは削除しません。対応サーバーでは指定したジョブが中断され、次の待機ジョブが開始される場合があります。古いサーバーでは ID が無視され、全体への中断が行われる場合があります。

再送信では `/queue` が返す prompt graph と `extra_data` を保持します。API が返さないサーバー固有のフィールドや送信オプションは保持できません。外部への副作用や有料 API ノードがあるワークフローでは、再送信の影響を確認してください。

## プライバシーとリモート接続

キューへのリクエストは設定した ComfyUI に送信します。更新の確認とダウンロードには GitHub を使用します。アクセス解析、テレメトリー、クラウドアカウントはありません。Sparkle のシステム情報送信は無効です。アドレスと更新設定は macOS の user defaults に保存されます。キューのレスポンスにはワークフローのメタデータが含まれる場合があります。

拡張機能は読み取り専用の JSON ルートを追加し、ComfyUI 内部の進捗 registry を利用します。reset 関数をラップしてジョブごとに監視を再登録します。WebSocket は開かず、キューの内容も変更しません。ルートの公開範囲はサーバーのネットワーク設定を引き継ぎ、**自動で localhost に限定されるわけではありません**。信頼できるネットワークや SSH ポート転送を利用してください。

GPUtw の非公開・パスワード保護インスタンスは「設定 → GPUtw にログイン…」から利用できます。正しいサービスを開き、「この ComfyUI を確認」でポートと最近のジョブを確認してから「このサーバーを監視」を押します。期限切れの場合は再ログインしてください。Cookie はアプリの WebKit で管理し、保護された出力にも同じログイン状態を使います。詳しくは [GPUtw とリモート設定ガイド](REMOTE_SETUP.ja.md)を参照してください。

汎用の API key・bearer token 入力には対応していません。GPUtw のログインデータはアプリの WebKit が管理し、サーバーブックマークや Agent ブリッジには保存しません。通常の API リクエストでは query-string 認証情報も未対応です。
