# リモート ComfyUI 設定ガイド

[English](../REMOTE_SETUP.md) · [简体中文](REMOTE_SETUP.zh-CN.md) · [繁體中文](REMOTE_SETUP.zh-TW.md) · **日本語**

GPUtw へのログイン、正しい ComfyUI サービスの選択、SSH 接続、リモート Mac のスリープ解除を説明します。監視するサーバーは一度に1台です。数値は、そのキューの実行中と待機中のジョブ数の合計です。

**対象バージョン：** GPUtw の内蔵ブラウザログイン、接続確認カード、接続状態の記号、Wake-on-LAN は現在の `main` ソースに含まれています。v1.5.2 のダウンロード版には含まれません。次のリリースまでは[ソースからビルド](README.ja.md)して利用してください。

## GPUtw の非公開・パスワード保護インスタンス

### ログインしてサービスを選ぶ

1. レンタル中のインスタンスを稼働させておきます。ComfyQueueBar の歯車 → **GPUtw にログイン…** を開きます。**ComfyUI アドレス**に `https://gputw.ai/dashboard` を入力して **接続** を押しても同じ画面を開けます。
2. アプリ内のブラウザでログインします。Safari や Chrome のログイン状態は自動共有されません。
3. インスタンスの **ComfyUI Web UI** を開きます。生成に別の設定済み HTTP ポートを使っている場合は、ダッシュボードからそのポートの Web UI を開いてください。パスワード保護されたポートでは GPUtw の画面にパスワードを入力します。
4. **この ComfyUI を確認** を押し、ポート、実行中／待機中の数、最近成功した3件を確認します。確認カードはキューと最新20件までの履歴を読み込みます。履歴を取得できない場合は不明と表示し、キューの検証に失敗した場合は確定できません。
5. **このサーバーを監視** を押すと、この GPUtw サービスを保存して監視先に選択します。**キャンセル**では現在の接続先を維持します。メイン画面とメニューバーのツールチップに選択中のポートが表示されます。
6. 必要なら **サーバー名** を `GPUtw · 8090 · 動画生成` などに変更し、**アドレスを保存** を押します。GPUtw から再接続しても既存のカスタム名は維持されます。

GPUtw のサービスアドレスは `https://<port>-<instance-id>.gputw.ai` 形式です。非公開サービスではダッシュボード経由で所有者のセッションを確立し、パスワード保護サービスでは最初にパスワード画面を表示します。既存のアクセスモードのまま利用でき、プラットフォーム API キーや公開ポートは不要です。[GPUtw Web UI](https://docs.gputw.ai/zh-TW/docs/jupyter-web-ui) と[ポートのアクセスモード](https://docs.gputw.ai/zh-TW/docs/ports)を参照してください。

### GPU が動いているのにアプリは 0 を表示する

同じ GPU インスタンスでも、ポートごとに独立した ComfyUI プロセスが動いている場合があります。例えば `8080` が標準サービス、`8090` が独自の動画生成環境という構成です。この番号は例であり、固定の割り当てではありません。ジョブを送信した ComfyUI のアドレスを確認してください。

1. 生成画面のポートと ComfyQueueBar のポートを比較します。
2. **この接続を確認**、または目的の保存済みサーバーを選び、切り替える前に最近のジョブを確認します。
3. ジョブ名と完了時刻を照合します。空のキューと無関係な履歴は、別サービスに接続している手掛かりです。履歴を取得できないことは、完了の証拠にはなりません。
4. 正しいサービスのキューが空なら、**最近完了したジョブ**と **失敗・中断** を確認します。更新の間にジョブが終了した可能性があります。

GPU 使用率や割り当て済み VRAM は ComfyUI のジョブ数とは別の指標です。現在のアプリは GPU 使用率の取得、全ポートの自動検出、複数サービスのキューの合算を行いません。選択中のキューを4秒ごとに確認します。0 と表示されたことだけを理由に同じジョブを再送信しないでください。

### メニューバーの記号

| 表示 | 意味 | 対処 |
| --- | --- | --- |
| `0` | 新しい有効な応答で、選択中のキューが空と確認できた | ジョブがあるはずならポートと最近の履歴を確認 |
| `1`–`99`、`99+` | 実行中と待機中のジョブ数の合計 | パネルで詳細を確認。ツールチップには正確な合計を表示 |
| `—` | 切断、認識できないキュー応答、または30秒以上更新なし | 接続を確認。現在のジョブ数は不明 |
| `!` | ログインが必要 | GPUtw に再ログインし、インスタンスの Web UI を開く |
| `…` | 最初のキュー応答を待機中 | 接続確認が終わるまで待つ |

有効なキュー応答を取得するとジョブ数の表示に戻ります。履歴やノード進捗の取得失敗だけで、正常なキューを切断扱いにはしません。0 だけでは成功を判断せず、成功を明示した履歴が必要です。

### ログイン、出力、復旧

- ログインの有効期限が切れたら **GPUtw にログイン…** を押し、正しいポートを開いて確認カードから確定します。ダッシュボードや Jupyter を開くだけでは ComfyUI サービスを特定できません。
- **GPUtw ログインを消去** は、このアプリのブラウザにあるアカウント／インスタンスのログインデータを削除します。他のブラウザのログアウトやレンタル GPU の停止は行いません。
- 保存するサービスアドレスから handoff のパス、query token、fragment を除きます。Cookie はアプリの WebKit ストアで管理し、ブックマークや Agent ブリッジのファイルには書き込みません。[安全性の説明](../../SECURITY.md)を参照してください。
- 画像とダウンロードにはログイン状態を適用します。保護された動画は一時ファイルにダウンロードしてからプレビューし、閉じる／切り替えると削除します。動画サムネイルはプレースホルダーを表示します。
- ノードの割合を表示するには、**同じリモート ComfyUI のインストール先**に進捗拡張機能が必要です。Mac のインストールボタンはローカル専用です。クラウドサーバーでは後述の手順を使ってください。
- 認証プロバイダーが内蔵ブラウザでのログインを許可しない場合は、既存の互換性のある SSH 接続を利用できます。ログインのためにアクセス制御を無効にしないでください。

## リモート Mac を起こす

Wake-on-LAN は保存済みサーバーごとの任意設定です。指定したネットワークインターフェイスの MAC アドレス宛てに UDP magic packet を送信します。停止した GPUtw レンタルインスタンスや ComfyUI の起動、SSH トンネルの確立は行いません。

### 設定と確認

1. 対象 Mac のシステム設定で、利用可能な **ネットワークアクセスによるスリープ解除** を有効にします。機種、電源、ネットワーク、macOS の設定によって対応状況が異なります。[Apple の説明](https://support.apple.com/en-gb/guide/mac-help/mh27905/mac)を参照してください。
2. ComfyQueueBar で対象の ComfyUI アドレスと名前を入力し、**アドレスを保存** を押します。ブックマークの保存時に、スリープ中のサーバーから応答がある必要はありません。
3. 保存済みアドレスの下の **Macを起こす** を展開し、対象インターフェイスの **MACアドレス**、ネットワークで許可された **ブロードキャストIPv4アドレス**、**UDPポート**を入力します。初期値は `255.255.255.255` と `9` です。実際のネットワークに合わせて変更してください。`02:11:22:33:44:55` は架空の入力例です。
4. **起動設定を保存**、続いて **今すぐ起こす** を押します。今すぐ起こす操作でも、表示中の設定を検証・保存してから送信します。
5. パケット送信の成功メッセージは、ローカルで送信できたことを示します。対象が起きて ComfyUI に接続できるようになったら、ブックマークを選択し、確認カードから **このサーバーを監視** を押します。
6. 必要なら **オフライン時に自動で起こす** を有効にして再保存します。そのサーバーを選択中に対象のネットワーク障害が起きると、サーバーごとに最大2分に1回パケットを送信できます。HTTP エラーやログイン失敗では送信しません。無効にするにはチェックを外して保存します。

ComfyQueueBar を実行する Mac は起動した状態にし、アプリを動かしておく必要があります。手動の **今すぐ起こす** は任意の保存済みサーバーに使えます。自動操作は選択中のサーバーだけが対象で、他のブックマークはポーリングしません。

### 対象が起きない場合

インターフェイスの MAC、スリープ解除設定、電源状態、UDP の宛先への到達性を確認してください。ブロードキャストはアプリの SSH トンネルでは運ばれず、ルーターや VPN を越えて自動転送されるわけではありません。利用可能な既存の LAN 経路を使ってください。アプリはルーター、ファイアウォール、中継サービスを設定しません。送信成功は実機のスリープ解除を保証しません。起きた後も ComfyUI と SSH トンネルが利用可能である必要があります。

## SSH 接続とリモート進捗の設定

例では Mac 側が `18188`、リモート ComfyUI が `8188` です。実際のポートに置き換えてください。

### 1. リモートサービスを確認

ComfyUI が動いているマシンで実行します。

```sh
curl --fail http://127.0.0.1:8188/queue
```

ComfyUI は既存の方法で起動してください。このアプリは ComfyUI やモデルをインストールしません。

### 2. Mac からトンネルを開く

```sh
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
  -L 127.0.0.1:18188:127.0.0.1:8188 user@your-server
```

`user@your-server` を置き換えます。SSH のポートが異なる場合は `-p 2222`、秘密鍵が必要なら `-i /path/to/private-key` を実際の値で追加してください。秘密鍵はコミットしないでください。Mac 側を `127.0.0.1` に限定するため LAN には公開されません。ターミナルを動かしたままにし、終了時は Control-C を押します。コンテナ内の ComfyUI では、SSH ホストから到達できるポートを指定してください。ホストとコンテナの localhost は同じとは限りません。

### 3. アプリを接続

```sh
curl --fail http://127.0.0.1:18188/queue
```

**ComfyUI アドレス**に `http://127.0.0.1:18188` を設定し、**接続**を押してキューと履歴を確認し、**このサーバーを監視**を押します。別のトンネルポートを使うので、Mac の `8188` で動く ComfyUI には影響しません。アプリは SSH 資格情報の保存、SSH の再接続、リモートマシンのスリープ抑止を行いません。切断時はトンネルを開き直してください。

### 4. リモート進捗拡張機能をインストール

Linux／macOS サーバーで実行します。

```sh
git clone https://github.com/sakmor/ComfyQueueBar.git
cd ComfyQueueBar
bash install-comfyui-extension.sh /path/to/ComfyUI
```

Mac の `comfyui_extension/ComfyQueueBarProgress/` をサーバーの `ComfyUI/custom_nodes/` にコピーしても構いません。サーバーに Swift は不要です。最終的なファイル位置は `ComfyUI/custom_nodes/ComfyQueueBarProgress/__init__.py` です。余分な階層を作らないでください。

Windows ではエクスプローラーで同じフォルダーを実際のインストール先の `custom_nodes` にコピーします。portable 版では通常 `ComfyUI` サブフォルダー内です。手動コピーなら Bash は不要です。Windows の SSH サーバーが必要なのは SSH 転送を使う場合だけです。

実行中の生成が終わってから、**その ComfyUI** を再起動します。Mac から同じトンネル経由で確認してください。

```sh
curl --fail http://127.0.0.1:18188/comfyqueuebar/queue-progress
```

## LAN または HTTPS で直接接続

信頼できる LAN では `http://192.0.2.10:8188` のようなアドレスを使えます。実際のサーバーアドレスに置き換えてください。適切なインターフェイスで待ち受け、ファイアウォールと macOS のローカルネットワーク権限で接続を許可する必要があります。

HTTPS リバースプロキシは `https://comfy.example.com` や `https://comfy.example.com/comfy` のパスプレフィックスを利用できます。ComfyUI API と `/comfyqueuebar/queue-progress` を転送し、macOS が信頼する証明書を使ってください。ローカル以外の HTTP は OS の転送セキュリティ設定による制約を受ける場合があり、既存のアプリ設定では SSH の loopback トンネルが使いやすい方法です。

内蔵ブラウザログインは現在 GPUtw が対象です。他のホストで独自の認証 header や query token が必要な場合は、互換性のある SSH など既存の信頼できる接続方法を使ってください。アプリ接続だけを目的に ComfyUI をインターネットへ公開しないでください。

自動テストは模擬 API とローカル UDP 受信を使います。すべての GPUtw アカウントでのログインや、すべての Mac／ネットワークでの実際のスリープ解除を証明するものではありません。
